# Auto Forex infrastructure

This directory is the TypeScript AWS CDK project root. It provisions a GitHub-connected delivery pipeline. Alpha and beta share the development account; prod uses the production account. The default region is `us-west-2`.

## Development

Use Node.js 22 or newer and npm. From this directory:

```sh
npm ci
npm run typecheck
npm test
npm run build
```

Tests synthesize isolated templates and exercise configuration resolution; they do not call AWS. `dist/` contains compiled TypeScript, and `cdk.out/` contains the cloud assembly generated by `npm run synth`.

| Command | Purpose |
| --- | --- |
| `npm run typecheck` | Check TypeScript without emitting JavaScript |
| `npm test` | Validate configuration, resource lifecycle, IAM trust, and pipeline ordering |
| `npm run build` | Compile TypeScript |
| `npm run bootstrap:pipeline` | Bootstrap the pipeline account with `auto-forex-pipeline` |
| `npm run bootstrap:targets` | Bootstrap dev and prod with their own profiles and trust the pipeline account |
| `npm run deploy:pipeline:full` | Deploy the complete pipeline using `auto-forex-pipeline` |
| `npm run synth -- -c target=pipeline` | Synthesize the initial pipeline without target deployment actions |
| `npm run synth -- -c target=pipeline -c bootstrapComplete=true` | Synthesize the full pipeline after target bootstrap |
| `npm run check` | Run type checking, tests, and synthesis using the current configuration |

The default target is `pipeline`. Missing required configuration fails with an error; application stages are not silently skipped.

## Configuration

[lib/config/environment.ts](lib/config/environment.ts) resolves settings in this order:

1. A non-empty `AUTO_FOREX_*` environment variable.
2. A value in [config/environments.yaml](config/environments.yaml).
3. A built-in default, where one exists.

Set `AUTO_FOREX_CONFIG_FILE` to read another YAML file. YAML strings also support `${VARIABLE}` and `${VARIABLE:-default}` interpolation. Undefined variables without a fallback are errors. Account IDs must be quoted strings.

For example, a local configuration file can contain:

```yaml
region: "${AWS_REGION:-us-west-2}"
accounts:
  dev:
    accountId: "${AUTO_FOREX_ACCOUNT_DEV:-111111111111}"
  prod:
    accountId: "${AUTO_FOREX_ACCOUNT_PROD:-222222222222}"
  pipeline:
    accountId: "${AUTO_FOREX_ACCOUNT_PIPELINE:-333333333333}"
```

The IDs in this example are placeholders. Application accounts must already exist before setting up the pipeline.

| Variable | YAML field / purpose |
| --- | --- |
| `AUTO_FOREX_REGION` | `region`; default `us-west-2` |
| `AUTO_FOREX_ACCOUNT_DEV` | `accounts.dev.accountId`; alpha and beta |
| `AUTO_FOREX_ACCOUNT_PROD` | `accounts.prod.accountId` |
| `AUTO_FOREX_ACCOUNT_PIPELINE` | `accounts.pipeline.accountId`; pipeline host account |
| `AUTO_FOREX_PROFILE_DEV` | Local-only profile; code default `auto-forex-dev` |
| `AUTO_FOREX_PROFILE_PROD` | Local-only profile; code default `auto-forex-prod` |
| `AUTO_FOREX_PROFILE_PIPELINE` | Local-only profile; code default `auto-forex-pipeline` |
| `AUTO_FOREX_GITHUB_OWNER` | `github.owner`; repository owner |
| `AUTO_FOREX_GITHUB_REPO` | `github.repo`; default `auto-forex` |
| `AUTO_FOREX_GITHUB_BRANCH` | `github.branch`; default `main` |
| `AUTO_FOREX_BOOTSTRAP_ENABLED` | `bootstrap.enabled`; default `true` |
| `AUTO_FOREX_BOOTSTRAP_EXECUTION_POLICY_ARN` | Policy used for bootstrap access and CloudFormation execution; default AWS `AdministratorAccess` |

Application accounts must already exist before pipeline setup. Account IDs use environment variables with the current account IDs as YAML fallbacks. Profile names do not live in YAML; they use local environment variables with code defaults.

## Initial setup and delivery

[Deployment instructions](../docs/deployment.md) cover these phases:

1. Verify the three profiles with `aws sts get-caller-identity --profile <profile>`.
2. Run `npm run bootstrap:pipeline` and `npm run bootstrap:targets`.
3. Run `npm run deploy:pipeline:full`, then authorize its GitHub connection in the AWS console.
4. Push to `main` to run the pipeline.

The target bootstrap command configures the standard CDK deployment roles to trust the pipeline account. Local profile names are used only by the bootstrap and deploy commands; CodeBuild receives account IDs, not local credentials.

Initial pipeline installation omits application stages because the target CDK roles do not exist yet. After successful bootstrap, the build synthesizes with `-c bootstrapComplete=true`; self-mutation adds the cross-account deployment actions and restarts execution. Use that context for later manual pipeline updates once the targets have been bootstrapped, so a manual deployment does not temporarily remove the application stages.

CI receives the resolved account IDs, region, GitHub coordinates, and bootstrap settings as CodeBuild environment variables. Changes to these deployment coordinates require updating the pipeline stack; local credentials and local configuration-file paths are not forwarded to CI.

| Path | Responsibility |
| --- | --- |
| `bin/auto-forex.ts` | Select the pipeline or all deployment target |
| `lib/config/environment.ts` | YAML loading, environment overrides, and validation |
| `lib/connection-source.ts` | GitHub source action with explicit CodeConnections permissions |
| `lib/stacks/pipeline-stack.ts` | GitHub connection, CodeBuild, self-updating pipeline, and application stages |
| `scripts/bootstrap-targets.ts` | Assume target roles and run the pinned CDK bootstrap CLI |
| `lib/stages/application-stage.ts` | Shared alpha/beta/prod deployment structure |
| `lib/stacks/application-stack.ts` | HTTP API, identity, price ingestion, storage, and deployment metadata |
| `test/` | Configuration and synthesized-template checks |

Application stacks deploy an API Gateway HTTP API, Cognito user pool, JWT-protected user operations, an ARM64 Fargate OANDA stream consumer, global AppConfig settings, SQS FIFO with a DLQ, Lambda functions, and DynamoDB `Users` and `Prices`. The Fargate task runs in public subnets with a public IPv4 address and no NAT Gateway. `Users` contains per-user stream settings keyed by Cognito `sub`; per-user OANDA tokens remain in Secrets Manager. AppConfig is initially deployed with ingestion disabled.
